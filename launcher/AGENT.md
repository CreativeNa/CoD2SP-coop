# CoD2 Co-op: инструкция для ИИ-ассистента на втором ПК

Ты помогаешь **игроку** подключить его копию Call of Duty 2 (одиночная кампания, Steam) к кооперативу с другим
игроком. Здесь только факты, команды и критерии. Игрок (человек) делает то, что требует его решения.

## Что это

`CoD2Coop.exe` (одиночный x86-файл) кладёт в папку игры мод `main\zz_coop.iwd` (скрипт миссии и экран CO-OP в
главном меню игры), мост `cod2net5.dll` и прокси `d3d9.dll`, который подгружает мост вместе с игрой (только
`CoD2SP_s.exe`). Игрок сам нажимает в **меню игры** CO-OP → HOST (хост) либо вводит адрес хоста и нажимает JOIN
(гость); мост обменивается с мостом другого игрока позицией игрока по UDP. Вторая фигура видна на экране,
враги видят игроков как обычно. Работает на всех 27 играбельных миссиях, обоим нужна **одна и та же новая** миссия (не сохранение). Фигура одета по кампании, повторяет позу, оружие, стрельбу, технику; убийства врагов зеркалятся.
Кликать в меню игры ты не можешь: это делает игрок, а ты проверяешь результат по логу.

## Границы (не нарушай)

- Менять только папку игры и то, что делает `CoD2Coop.exe`: `main\zz_coop.iwd`, `main\zz_coop_lang.iwd` (тексты меню на языке игры), `d3d9.dll`, `cod2net5.dll`,
  `coop_port.txt`, `coop_peer.txt`, `coop5.log`, `coop_net.csv`. Остальное в игре, Steam, реестр не трогай.
- **Чужой `d3d9.dll` (ReShade и т. п.) не заменяй и не удаляй.** Установщик сам его не трогает и говорит об
  этом; тогда меню игры подключиться не сможет, остаётся запасной путь `host`/`join` из `CoD2Coop.exe`
  (установка с `--no-autoload`). Решение за игроком.
- **Не отключай и не меняй брандмауэр и антивирус сам.** Скажи игроку, что нажать (см. «Брандмауэр»). Если
  антивирус заблокировал `CoD2Coop.exe`, объясни игроку, что программа внедряет DLL в игру (поэтому и
  срабатывает), и пусть он сам решит, добавлять ли исключение. Не обходи защиту.
- **Не запускай и не закрывай игру без разрешения игрока.** `install` требует закрытую игру, `connect` —
  запущенную: попроси игрока, дождись «готово».
- Только одиночная игра. В мультиплеер CoD2 (PunkBuster) не заходить.
- Не отправляй логи никуда, кроме адреса, который назвал игрок (`logs --send <ip хоста>`).
- Если exe сообщает «NOT the expected build» (хэш `CoD2SP_s.exe` не `AB17A89C…2281`), ничего не делай и сообщи
  игроку: программа сделана под Steam-версию 1.3, другие сборки она не меняет.

## Команды (все без меню; опции в любом порядке)

```
CoD2Coop.exe check                                  состояние: игра, хэш exe, мод, автозагрузка, процесс, адреса этого ПК
CoD2Coop.exe install                                мод + экран CO-OP + мост + прокси d3d9.dll (игра ЗАКРЫТА)
                                                     (с 0.9.26 мод собирается НА ЭТОМ ПК из файлов игры через PowerShell, ~30 с;
                                                      при ошибке сборки программа печатает конец журнала сборки - перешли его целиком)
CoD2Coop.exe install --no-autoload                  только мод: подключение командами host / join из этой программы
CoD2Coop.exe host --seconds 30                      (запасной путь, без автозагрузки) ХОСТ: адрес гостя не нужен
CoD2Coop.exe join 26.x.x.x --seconds 30             (запасной путь, без автозагрузки) ГОСТЬ: адрес хоста
CoD2Coop.exe connect --peer 26.x.x.x --seconds 30   (запасной путь) оба адреса вводятся вручную
CoD2Coop.exe logs --send <ip хоста>                 zip логов рядом с exe + загрузка хосту (TCP 27301)
CoD2Coop.exe uninstall                              убрать мод и файлы настроек (логи остаются)
```

Опции: `--game DIR` (если игру не нашли через Steam), `--port N` (слушать, по умолчанию 27201),
`--peer-port N` (порт напарника, 27201), `--logport N` (пересылать строки лога хосту на UDP N, по умолчанию
27300, `0` = выкл), `--seconds N` (показать живой лог N секунд и вернуться; без него — до Ctrl+C, для
агента всегда ставь `--seconds`), `--verbose` (включая строки `gsc readback`).
Код возврата 0 = успех, 1 = проблема, 2 = неверные аргументы.

## Порядок работы

1. `CoD2Coop.exe check`. Нужно: хэш `(matches)`, `Mod: installed`, адрес Radmin `26.x.x.x` в списке.
   Нет адреса Radmin → Radmin VPN не запущен или игрок не в сети напарника: пусть запустит и подключится.
2. Игра закрыта → `install` (при необходимости спроси игрока, закрыта ли игра). Ошибка записи значит, что
   игра запущена или нет прав на папку.
3. Игрок запускает игру через Steam; в главном меню должна быть кнопка **CO-OP**. Выясни его роль.
   **Хост:** CO-OP → HOST (адрес гостя не нужен). **Гость:** CO-OP → в поле «Host address» оставить `auto` → JOIN
   (хост найдётся по его сигналу в сети). Если автопоиск не сработал, нужен адрес хоста (`26.x.x.x` Radmin или LAN):
   игрок видит свой адрес в `check` или в окне Radmin, гость стирает `auto`, вводит адрес и жмёт JOIN. Нажатие
   доходит до моста за ~3 секунды. Порядок не важен. Ждёшь его «нажал».
4. Проверь по `coop5.log` (папка игры) строки `menu: dvars found`, `menu: coop_cmd='host'` или `'join'`, `menu: HOST …`
   / `menu: JOIN <ip> …`. Игрок начинает **новую** миссию (любую, одну и ту же у обоих); дальше у хоста `peer learned: <ip>`, потом `tx`/`stats`.
5. Оцени остальное по таблице ниже. Если нужна диагностика — `logs`. Запасной путь без меню игры: установка с
   `--no-autoload`, затем `host --seconds 30` (хост) и `join <адрес хоста> --seconds 30` (гость).

## Как читать лог

Строки `coop5.log` имеют вид `[порт] чч:мм:сс.мсс текст`. Полный файл — в папке игры.

| Строка | Значит |
|---|---|
| `=== cod2net5 0.9 (in-game menu) …, game exe N bytes, pid P ===` | мост загружен (вместе с игрой) |
| `mode: in-game menu …; nothing listens until then` | мост ждёт нажатия HOST / JOIN в меню; порт не открыт |
| `autoloaded: ignoring leftover coop_port.txt / coop_peer.txt` | остались файлы от старого способа; меню главнее, мост их игнорирует |
| `menu: dvars found (coop_cmd …, coop_ip …)` | мост нашёл переменные, которые ставит меню |
| `menu: coop_cmd='host' coop_ip='…'` / `menu: HOST (listen 27201 …)` / `menu: JOIN <ip> …` | команда из меню принята |
| `menu: JOIN needs 'auto' or a valid IPv4 address …` | в поле «Host address» не `auto` и не адрес a.b.c.d; игрок исправляет и жмёт JOIN ещё раз |
| `host: announcing on the network (UDP 27202, N broadcast targets)` | хост рассылает «я здесь»; N — число адресов рассылки (255.255.255.255 и по одному на сетевую карту) |
| `menu: JOIN auto - looking for a host …` / `discovery: listening for a host beacon on UDP 27202` | гость в режиме автопоиска слушает сигнал хоста |
| `discovery: host found at <ip> (its beacon)` | автопоиск сработал: гость подключился к этому адресу |
| `discovery: no beacon for 10 s; trying the last host <ip>` | сигнал не пришёл: используется хост из прошлого раза (`coop_lasthost.txt`), прослушивание продолжается |
| `discovery: cannot listen on UDP 27202 …` | порт 27202 занят; игрок вводит адрес хоста вручную |
| `remembered the host <ip> for the next 'auto'` | хост ответил гостю; адрес записан в `coop_lasthost.txt` |
| `another bridge is already running in this game process …` | в процессе уже есть мост (например, старый); перезапустить игру |
| `host mode: waiting for the guest's first packet …` | хост ждёт гостя; пока гость не пришлёт пакет, хост ничего не отправляет |
| `peer learned: <ip> (first pose packet)` / `peer switched to <ip> …` | хост запомнил гостя / перешёл на нового, когда прежний молчал 5 с |
| `listen on all interfaces (peer is remote)` / `udp bound 27201` | слушает, привязка прошла |
| `waiting for a mission: the mod's cvars do not exist yet` | игрок не в миссии или мод не установлен; мост ждёт до 20 мин |
| `structs px=… py=… pz=…` | мост нашёл переменные мода: миссия идёт |
| `local state cvars …` | мод публикует состояние игрока |
| `tx -> <ip>:<порт>` и `tx N: x y z yaw seq us` | отправляет вашу позу напарнику |
| `pkt N: …`, `apply N …` | получает позу напарника и применяет |
| `stats tx=… rx=… echo=… lost=… reordered=… \| rtt ms min/avg/max=… \| max rx gap … ms` | раз в 5 с: потери, RTT |
| `peer silent for > 5 s` / `peer is sending again` | напарник замолчал / вернулся |
| `bind N FAILED err=10048` | порт занят прежним мостом в этом процессе игры: **перезапустить игру** (или другой `--port` на обоих ПК) |
| `rx rejected (out of range)` | пришло нечисловое или вне диапазона значение |

`coop_net.csv`: `wall,t_ms,dir,seq,x,y,z,yaw,note`; `dir` = `tx`, `rx`, `echo` (в `note` `rtt_ms=…`).

**Связь есть**, если выполнено всё: `tx` строки идут, `stats` показывает `rx` растущим, `echo` > 0 и `lost` не
растёт быстро. Значения RTT и допустимых потерь я не задавал и не мерил на втором ПК: оценивай по тому, что
игрок видит в игре, и сообщай цифры как есть.

## Диагностика, в порядке вероятности

1. `tx` идёт, `rx` 0: **брандмауэр**. Windows считает сеть Radmin «Общедоступной» (Public), а для неё входящий
   UDP блокируется. Попроси игрока открыть Безопасность Windows → Брандмауэр → «Разрешить работу с
   приложением» → `CoD2SP_s.exe` → отметить и «Частная», и «Общедоступная» (это **его** действие). Либо он
   нажимает «Разрешить» в окне Windows при первом запуске. Проверь также `ping 26.x.x.x` до напарника
   (в Radmin): нет ответа → проблема в Radmin, не в игре.
2. Нет `tx`, есть `waiting for a mission`: игрок не в миссии, или мод не стоит, или загрузил сохранение.
   Нужна новая миссия и `install` при закрытой игре.
3. `port … FAILED`: перезапуск игры (см. таблицу).
4. `rx` растёт, но фигуру не видно: попроси игрока описать, где стоит напарник; фигура не твёрдая, стоит на
   земле у позиции напарника (миссия одна и та же, старт в одной точке).
5. Не поможет `connect` повторно: после неудачи с занятым портом — только перезапуск игры.

## Что вернуть хосту

1. `CoD2Coop.exe logs --send <ip хоста>` (если на хосте запущен `python log_collector.py`) или просто zip рядом с
   exe — игрок отправит его сам.
2. Короткий отчёт: версия (первая строка вывода, `CoD2Coop 0.8.0`), результат `check`, команда `connect`, последняя строка `stats`,
   были ли `peer silent` и `FAILED`, что видел игрок. Без догадок: отмечай, что проверено логом, а что со слов.
3. Не включай в отчёт имя пользователя Windows и полные пути (в логах их нет; не добавляй свои).
